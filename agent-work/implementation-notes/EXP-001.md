# EXP-001 — Implementation notes

## Scope delivered

EXP-001 implements EXP-001 through EXP-007, EXP-010 through EXP-015, active-record exclusion for EXP-016, and Expense create/update portions of AUD-001 through AUD-003. EXP-008, EXP-009, the recycle bin, delete/restore operations, and the audit-history viewer remain deferred to EXP-002. No Transfer, Dashboard, Report, Excel workflow, Telegram/n8n, Backup, authentication, tenancy, accounting, or Claims feature was added.

The active product, architecture, data-model, security, testing, acceptance, backlog, OpenAPI, and prior CORE/PRJ/CAT/PAY delivery records were reviewed before implementation. The committed CORE-001 `Expense` and `Attachment` models satisfy this slice without a schema change.

## Approved API contract

All routes use `/api/v1`:

- `GET /expenses` — active list with optional `projectId`, inclusive `from`/`to`, category, subcategory, Payee, payment method, source, trimmed search, NEWEST/OLDEST sorting, and bounded pagination.
- `POST /expenses` — create with `projectId` in the JSON body and trusted `WEB` source.
- `GET /expenses/{expenseId}` — active Expense detail.
- `PATCH /expenses/{expenseId}` — edit without changing Project or source.
- `GET /expenses/{expenseId}/attachments` — private metadata only.
- `POST /expenses/{expenseId}/attachments` — one multipart `file` after Expense creation.
- `GET /attachments/{attachmentId}/content` — private API stream.

Pagination defaults to page 1 and page size 25, caps page size at 100, and returns total items/pages. Deleted Expenses are excluded and resolve as not found through this contract. Expense delete and restore paths were removed from active OpenAPI pending EXP-002.

## Amount calculation

`ExpenseAmountService` is the authoritative server calculation boundary. It uses Prisma Decimal and existing centralized decimal helpers only:

- Calculated mode requires positive quantity and unit price, rejects a client amount, multiplies at exact four-decimal precision, and persists a two-decimal `ROUND_HALF_UP` result.
- Manual mode requires a positive two-decimal amount and may retain only one calculation input as informational data.
- Update resolves a complete financial state, supports calculated/manual transitions, and rejects an incomplete state without a manual amount.
- The browser preview uses scaled `BigInt` arithmetic and the same half-up rule; it is display-only and the server remains authoritative.

No financial value is converted through JavaScript `number`, `Number(...)`, or `parseFloat`. `Expense.amount` is the only persisted authoritative result.

## Validation and persistence

Creation asserts an existing active Project, active Category, effective active Subcategory belonging to that Category when supplied, and active Payee when supplied. Project state, classification validation, Payee validation, Expense persistence, and audit append occur through bounded application services.

Updates preserve Project and source. Deleted Expenses return not found and archived Project Expenses are read-only. An unchanged inactive Category, Subcategory, or Payee remains valid for historical editing; clearing optional Subcategory/Payee references is allowed; a different non-null assignment must be active. Imported null Category records may remain null but normal web creation always requires Category. No persisted `غير مصنف` record is created.

Create and meaningful update append safe immutable audit snapshots in the same Prisma transaction. Decimal values serialize as strings, correlation ID is retained, and no-op updates produce no event. Project, Payee, and Agreement totals remain derived from the Expense table and update immediately without stored summary columns or Redis.

## Listing and query behavior

The list query performs one bounded PostgreSQL row query plus one count query. Project, Category, Subcategory, Payee, and Attachment metadata are loaded through one Prisma include rather than N+1 queries. Filtering, inclusive dates, search, sorting, skip/take pagination, and `deletedAt: null` are applied in PostgreSQL. Deterministic order is Expense date, creation time, then ID.

Project-context pages use the same global endpoint with `projectId`; there is no duplicate Project Expense API. Search uses literal substring matching over description, invoice number, notes, Payee name, and Payee company. The existing Project/date and classification/Payee indexes are reused. Global substring search can still require a PostgreSQL scan near the 100,000-row target; no unapproved trigram index, migration, external search engine, or cache was introduced.

## Private attachments

Validated environment settings define allowed MIME types, per-file bytes, and per-Expense count. The approved runtime values are JPEG, PNG, WebP, and PDF; 10 MiB; and 10 attachments. Upload rejects empty content, checks magic bytes against the declared MIME type, generates the private object key server-side, preserves a separately validated original name, and stores SHA-256 and metadata in PostgreSQL.

Object upload precedes a database/audit transaction. A database or audit failure triggers best-effort removal of the uploaded object; storage failure creates no metadata. A rare compensation failure is logged as an object-key-only operational event and may require operator cleanup, which is the unavoidable distributed-transaction boundary.

Retrieval validates active Expense visibility, obtains a private object stream, and streams it without whole-file buffering. Responses use safe type/length metadata, `Cache-Control: private, no-store`, and sanitized RFC 5987 content disposition. Archived Project attachments remain readable; writes are rejected. No public URL, signed URL, storage credential, OCR, transformation, or removal endpoint is exposed.

## Web application

- `/expenses` provides the Arabic RTL active list, all approved filters, search, sorting, pagination, source and attachment indicators, loading/empty/no-results/error states, and Project-context links.
- `/expenses/new` provides active Project/Category/Subcategory/Payee selection, manual and calculated modes, exact preview, date-only input using Cairo's calendar date, and links to the existing Category and Payee management flows.
- `/expenses/[expenseId]` provides detail/edit, archived read-only state, metadata, attachment upload, and private attachment download through a same-origin streaming route.

The shell now exposes `المصروفات`; Project detail links into its filtered Expense context. Controls are Arabic, RTL, light, keyboard accessible, touch-sized, and responsive. There is no source control, delete/restore action, login/account UI, or legacy `مبلغ العملية` field.

## Database and reversible decisions

The Prisma schema, documentation schema, and `20260801000000_expense_tracker_foundation` migration are unchanged. No seed data or new index was added.

Reversible implementation choices are the same-origin Next.js streaming proxy, accessible management links instead of duplicating inline Category/Payee CRUD dialogs, literal database substring search, and server-rendered URL query state as the authoritative list context.

## Deferred

Expense soft delete, restore, recycle bin, delete/restore audit events, and audit-history UI remain EXP-002. Transfers and funding writes remain TRF-001. Dashboard, Reports, import/export, Telegram/n8n, and Backup remain their bounded tasks. Per the current dependency queue, TRF-001 is next eligible; neither it nor EXP-002 was started.
