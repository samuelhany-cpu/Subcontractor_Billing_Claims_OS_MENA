## Approved OpenAPI REST Contract (`docs/schemas/openapi.yaml`)

All endpoints use `/api/v1`:

- `GET /api/v1/transfers` — Query params: `projectId` (optional UUID), `from`, `to`, `status` (`ACTIVE`, `DELETED`, `ALL` - default `ACTIVE`), `sort` (`NEWEST`, `OLDEST` - default `NEWEST`), `page` (default 1), `pageSize` (default 25, max 100).
- `POST /api/v1/transfers` — Create incoming transfer (`projectId`, `transferDate`, `amount`). Server-assigned `source = WEB`.
- `GET /api/v1/transfers/{transferId}` — Detail view (active or soft-deleted).
- `PATCH /api/v1/transfers/{transferId}` — Update `transferDate` and/or `amount`. Immutable `projectId` and `source`. No-op creates no AuditEvent.
- `POST /api/v1/transfers/{transferId}/delete` — Soft-delete transfer (sets `deletedAt`).
- `POST /api/v1/transfers/{transferId}/restore` — Restore soft-deleted transfer (clears `deletedAt`).

---

## Business & Funding Formulas

- `totalIncomingTransfers = sum of active Transfers (deletedAt: null)`
- `totalFunding = openingBalance + totalIncomingTransfers`
- `availableBalance = totalFunding - totalExpenses`
- Decimal handling strictly uses `Prisma.Decimal` and `parseMoney`/`serializeMoney` without JavaScript `number` or `parseFloat` financial math.
- Soft-deleted transfers are excluded from active funding totals.
- Restoring a transfer returns it to funding totals.

---

## Transaction Isolation & Audit

- All transfer mutations (`CREATE`, `UPDATE`, `DELETE`, `RESTORE`) execute in a Prisma transaction alongside `AuditService.append`.
- Audit events record entityType `'Transfer'`, exact stringified Decimals, correlation IDs, and before/after state snapshots.
